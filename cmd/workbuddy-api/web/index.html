编辑
规则很简单：左边写客户端会调用的模型名（可以随便起，如 my-cheap-code）， 右边写真实要走的 渠道/模型名。
例：my-cheap-code = glm/glm-5.2；通配：claude-* = workbuddy/glm-5.2。 这里创建的是「固定走某一个模型」的别名；若要让多个渠道候选自动切换，用下方的「多候选自定义模型」。
「模型名」怎么填？ 别猜、别手敲——用下方输入框的下拉候选直接选，那里列出的是各渠道当前真实可用的模型名（含费率），选中的就是正确写法。
· 渠道名固定是这几种：workbuddy、workbuddyai、traework、traecode、qodercn、qodercom、qwenwork（千问办公）、glm（智谱清言）、monkeycode、raccoon（小浣熊）、loomy、customopenai（自定义渠道）。
· 自定义渠道：模型名写 customopenai/<模型id>，其中「模型 id」必须与你在设置里为那个实例填写的模型列表一致（不是随便起，对端上游返回什么就填什么）；没在「自定义渠道」区添加实例时，这个前缀不可用。
· 小浣熊模型要保持 sn- 前缀，如 raccoon/sn-sensenova-6-8-flash、raccoon/sn-glm-5-3-flash；去掉前缀会被上游当成未知模型。
· 其余渠道用裸名即可，如 workbuddy/glm-5.2、qodercn/kimi-k3。
· 不确定就点开「费率」页看模型清单，或从上方下拉候选中选一个。

WebAPI 接入 · 网页版模型变免费 OpenAI 接口
这三个项目本质是同一件事：在本机或飞牛上跑一个小服务，把网页版模型（DeepSeek / Kimi / GLM / Gemini / Loomy） 转成 OpenAI 兼容接口，再把它当作「自定义账号」接进网关。
区别只在于「跑哪个项目、怎么登录」——下面按推荐顺序排好了。
完整教程：从零接入一个 WebAPI 源
  1. 选一个源并在飞牛/电脑上跑起来：能装 FPK 的优先（duruoxian、Loomy 都有现成包）， 零依赖的 gemini-web2api 直接 pip install httpx && python gemini_web2api.py。
  2. 确认它在监听：curl http://127.0.0.1:端口/v1/models，返回 {"data":[...]} 即正常； 返回 401 也正常（说明要 key）。
  3. 拿到它的 API Key：duruoxian 在管理面板「API Key」页生成 sk-...； gemini-web2api 零鉴权，随便填（如 sk-any）；Loomy 按其文档。
  4. 登录平台账号：duruoxian 在面板「浏览器登录」扫码；Loomy 必须先在有屏幕的电脑上扫码， 再把 loomy-profile/ 整份拷进飞牛；gemini 不需要登录。
  5. 填进网关：点下方对应卡片的「填入」，再点「添加」；保存后重启网关生效。
  6. 验证：/v1/models 里出现 customopenai/<模型>， 发一句「只回复两个字：通了」能收到真实回复即成功。账号列表会显示 webAPI 标签。
三个必踩的坑：①地址写 127.0.0.1 时它指网关所在的那台机器——服务跑在电脑上就要填电脑的局域网 IP， 跑在飞牛上才用 127.0.0.1；②并发别开大：免费源建议「并发上限」设 1~2，否则容易被风控； ③Cookie 会过期：表现为模型列表变空或 401，重做一次登录即可，网关配置不用改。
风险提示：网页版逆向接入可能触发平台风控甚至封号，仅供个人自用，不要对外提供服务。
自定义渠道（OpenAI 兼容上游）
能接什么：任何提供 POST {base_url}/chat/completions 且返回 OpenAI 格式的服务—— 官方/云厂商（OpenAI、DeepSeek、Kimi、智谱、通义、火山方舟、硅基流动、OpenRouter、Gemini 的 OpenAI 兼容端点…）、 自建推理（Ollama /v1、LM Studio、vLLM、llama.cpp）、中转站（one-api / new-api 等）都行。
要填什么：base_url（通常以 /v1 结尾）+ api_key + 模型 id。模型 id 不用猜—— 点「拉取模型」会自动向对端 /models 取列表并勾选。

配置说明

1. 添加账号后自动完成登录（WorkBuddy 国际版无需手动签到，定时自动领取日活奖励；Qoder 渠道无签到活动，仅 API 转发）。

2. AI 客户端配置：Base URL http://127.0.0.1:7863/v1，API Key 见页面顶部。

3. 支持三种接口协议：
· OpenAI Chat：POST /v1/chat/completions（旧版客户端）
· OpenAI Responses：POST /v1/responses（codex CLI）
· Anthropic Messages：POST /v1/messages（claude CLI，Base URL 不带 /v1）
Anthropic 客户端用 x-api-key 或 Authorization: Bearer 均可。

4. 模型 ID 建议带渠道前缀：workbuddy/<model>、workbuddyai/<model>、traework/<model>、qoder/<model>； 也支持裸名（走「设置 → 模型路由」的 默认渠道 / 映射表 配置）。

5. 账号显示名可点击卡片上的名字直接修改；顶栏齿轮进入统一设置（监听 / API-Key / 模型路由 / 渠道上游代理）。

6. 渠道上游代理：给单个渠道的上游请求配置独立代理（http/https/socks5），留空即直连； OpenCodeZen 的区域限制模型需经代理访问时可在此配置。

7. 积分会随聊天消耗实时变化，"全部刷新积分"可即时获取最新余额。

8. 日志文件位于 exe 目录下 data/app.log，可从托盘菜单"查看日志"打开。

9. 退出程序：右键托盘图标选择"退出"。
